# Task Ux

Read the task, story, and product context and user research that directly inform the task; inspect the affected flow. Include only information relevant to the task, and omit unrelated research and caveats. Use simple, concise wording and omit obvious statements. Combine the journey and affected screens into one flow; use a diagram such as Mermaid when it clarifies the flow. Record relevant evidence and unresolved user needs. Document recovery paths and boundaries as a concise scenario table with the situation and expected behavior; use a state diagram when transitions need it. Label simulated research and untested assumptions. Include questions only when their answers affect the flow; missing screenshot visibility does not prove a feature is absent. Follow the project's documentation conventions.


Write the result to `docs/tasks/<task>/ux.md`, using the existing task directory or a descriptive kebab-case name. Preserve existing content and creation metadata, link relevant phase documents, and ask before overwriting unrelated work.
