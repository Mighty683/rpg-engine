# Task Story

Read the task, product context, and relevant user evidence. Follow the project's task conventions. State the user, desired capability, and benefit, then list observable outcomes needed to bound the work. Keep proposed controls and architecture for later stages. Distinguish evidence from hypotheses and do not invent research.


Write the result to `docs/tasks/<task>/story.md`, using the existing task directory or a descriptive kebab-case name. Preserve existing content and creation metadata, link relevant phase documents, and ask before overwriting unrelated work.
