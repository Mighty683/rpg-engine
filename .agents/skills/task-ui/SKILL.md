# Task Ui

Read the task, story, UX research, design guidance, and affected UI. Follow the project's documentation conventions. Describe screen changes, placement, controls, copy, states and interactions. Cover focus, keyboard behavior and draft preservation when relevant. Reuse established components and design tokens; justify new ones when needed. Keep module internals in the technical design and do not redesign the agreed flow.


Write the result to `docs/tasks/<task>/ui.md`, using the existing task directory or a descriptive kebab-case name. Preserve existing content and creation metadata, link relevant phase documents, and ask before overwriting unrelated work.
