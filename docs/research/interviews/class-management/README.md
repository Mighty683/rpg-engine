# Class management — simulated persona reviews

**Date:** 2026-11-12  
**Method:** Independent, desk-based walkthroughs of the [first static prototype](../../../tasks/class-management/ui.md) and the [UX journey](../../../tasks/class-management/ux.md), using the provisional personas. One design iteration addresses selected hypotheses, followed by a separate desk review of the revised markup. No participant was recruited or interviewed. No task completion, timing, user behavior, or verbal feedback was measured.

- [Game master review](game-master.md)
- [Player review](player.md)

The prototype exposes screens through gallery controls; its buttons do not perform actions. The reviews consider what each screen communicates, not whether a person can navigate, save, copy, remove, or recover. Example names and numbers are illustrative. The two persona perspectives are assumptions, not representative users or evidence of usability. Predictions and recommendations below are interpretations, not quotations or observed participant feedback.

## Iteration and follow-up

The first review identified potentially ambiguous editing scope and consequences for the GM, and potentially ambiguous benefit application for the player. The revised prototype makes the editing scope explicit in the editor, names the game in the removal warning, clarifies copy independence and distinguishes applied modifiers from text effects. It also corrects the library breadcrumb. These are proposed wording changes, not validated solutions. The second review is a source-level inspection, not a live usability test; remaining questions are recorded in each report.

Next, run moderated sessions with real GMs and players on an interactive prototype. Ask participants to explain which version they are editing, predict the consequences of copying and removing a skill, and interpret a character's benefits. Include recovery, narrow screens, keyboard access, and independently verify rule calculations. Record actual observations separately from interpretation.
