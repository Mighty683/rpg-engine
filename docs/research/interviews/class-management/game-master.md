# Class management — simulated GM review

**Date:** 2026-11-12  
**Persona:** [Provisional game master](../../personas/game-master.md)  
**Status:** Simulated desk review; no GM was interviewed. [Method and limitations](README.md).

## First walkthrough and predicted feedback

- **Prepare and edit:** The list identifies library or game context, but the editor's breadcrumb previously said “Classes / Guardian” in either context. A GM entering the editor may miss which copy will change. The static editor shows one skill but does not expose the full benefit or skill form, validation, or save behavior.
- **Copy:** The copy screen names The Crystal Road and says the copy can be edited separately. A GM may still wonder whether later library edits propagate. The screen does not show a detailed class review or demonstrate copying.
- **Remove:** The warning lists Rowan Ash and Nera Vale and says the skill is removed from them. Naming the game in the consequence may help identify the scope. The prototype cannot demonstrate cancellation, confirmation, focus, or what happens if character usage changes.
- **During play:** A benefits view distinguishes an applied modifier and text, but the handling of other edits, full class removal, and skill choices or ranks remains undecided in the journey.

## Iteration and second review

The editor now states whether changes affect the library or this game; the breadcrumb identifies that context. Copy wording explicitly says later library edits do not update the game copy. The removal warning names the game as well as affected characters. Source inspection confirms those statements are present in the revised static screens. It does not establish that the wording is noticed or understood, or that the list of characters is complete and current in a real operation.

## Questions for real GMs

1. Can they identify which copy they are editing and predict whether a later library edit reaches a game?
2. What information do they need before copying or confirming removal, and do they understand the effect on every affected character?
3. How should edits to skills, removal of a whole class, and rank-dependent benefits affect existing characters? How should the interface handle failed or stale removal checks?
4. Can they complete and recover from the flows with keyboard and on a narrow screen? These interactions are not implemented in the static prototype.
